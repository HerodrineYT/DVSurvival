# Переработка DVSurvival 0.2.0

## Граница работы

По согласованию сохранены все возможности и проверенные адаптеры игры. Это не переписывание каждой строки: совместимые форматы данных, предметные модели, локализация, проверки сетевых команд и исправления штатных API переиспользуются.

Заново написаны расчётный конвейер, планировщик сессии, хранилище активных игроков и подготовка отображаемых значений. Перенос адаптеров в отдельные файлы сам по себе оптимизацией не считается.

## Структура

| Слой | Ответственность |
| --- | --- |
| Core/Simulation | NeedsEngine, ThermalSystem, VitalitySystem, ProvisionSystem, TraumaSystem: расчёты без Unity, файлов, сетевых вызовов и чтения системного времени |
| SimulationInputs | Неизменяемые значения окружения и правил; расчёт не меняет общие настройки и буферы окружения |
| Core/Runtime | SessionSchedule с отдельным учётом игрового и активного реального времени; PlayerSlots с прямым доступом по byte-ID и плотным обходом |
| Game/SurvivalRuntime | Последовательность фаз сессии и запуск расчёта для каждого игрока |
| Game/Runtime | Сохранённые границы интеграции: сон, команды, сеть, отопители, окружение, возвращение домой, жизненный цикл и публикация состояния |
| Game/NeedsPresenter | Сохранённые строки HUD: форматируется только изменившееся поле |
| SurvivalSimulator | Совместимый вход для существующих адаптеров, делегирующий расчёты новому ядру |

Активные игроки хранятся в заранее выделенных слотах на 256 возможных byte-ID. Обход выполняется по занятым слотам, а не по всем 256 позициям. Удалённые ссылки очищаются.

Расписание не создаёт очередь догоняющих кадров. Потребности следуют календарю мира, а постепенное лечение аптечкой — реальным секундам активной игры. Обработка точных интервалов сна и сетевой защиты от повторов сохранена.

| Температура | Погода, вода, укрытия, офисы, кабины, открытые окна и двери, обороты, отопитель и вентилятор, топки; интеграция DVSeasons |

## Проверки

Автотесты старого функционала сохранены. Дополнительно проверяются:

- 45 000 событий нового и замороженного прежнего расчёта: ход времени, сон, предметы, травмы; сравнение всех полей состояния;
- независимость игроков и неизменяемость входных данных;
- случайные подключения и удаления в PlayerSlots;
- отсутствие выделений памяти в прогретом расчёте, пустой обработке календаря и неизменившейся презентации;
- изменение правил при редактировании настроек;
- сборка и загрузка с библиотеками Derail Valley, обязательными зависимостями, с MultiplayerAPI и без него;
- отдельный Unity-стенд для офисов, стриминга и реестров объектов.

Замороженный прежний расчёт находится только в Tests/Reference. В рабочие DLL он не входит.

Замер прогретых участков на 10 000 вызовов (.NET 8, 30 сентября 2026):

| Участок | Прежняя оптимизированная 0.1.2 | 0.2.0 |
| --- | --- | --- |
| Обычный шаг расчёта | 0 байт/вызов | 0 байт/вызов |
| Пустая очередь календаря/сна | 32 байта/вызов | 0 байт/вызов |
| Расчёт с некорректным полем окружения | 56 байт/вызов | 0 байт/вызов |

Повторение замера: Tools/verify_rebuild.ps1 -BaselineDll 'путь к прежней DVSurvival.Core.dll'. Отчёт содержит SHA-256 и MVID сравниваемых DLL; базовая DLL не входит в публичные архивы.

Команды повторной проверки:

```powershell
Tools/build.ps1 -DVInstallDir 'путь к Derail Valley'
Tools/verify_climate.ps1 -DVInstallDir 'путь к Derail Valley'
```

Второй скрипт требует локальный Unity Editor 2019.4.40f1 (путь задаётся через -UnityEditor) и сам создаёт отдельный проект стенда в artifacts/verification/UnityClimate. Он не открывает рабочие проекты и игровые сохранения. Основная сборка Unity Editor не требует.

## Ограничения доказательств

Нулевые выделения памяти относятся к конкретным изолированным прогретым участкам, а не ко всему моду или игровому кадру. Чистое ядро прежней оптимизированной 0.1.2 также не выделяло память на нормальном шаге; это не новое достижение 0.2.0.

Сравнение расчётов и стенды не доказывают отсутствие всех ошибок в настоящей поездке. Перед публикацией нужны одиночная и совместная поездка с хостом и клиентом: сон на 10 часов с перемоткой и без неё, работа двигателя после сна, травмы, отопители, расходники, возвращение домой и повторная загрузка сохранения. Для оценки FPS сравнивать одинаковый маршрут, погоду, составы и игроков.

Сборка не установлена в игру автоматически. Исходники до переработки сохранены отдельно в artifacts/backups/before-rewrite-20260930/source-before-rewrite.zip.
